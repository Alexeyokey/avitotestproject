F_hybrid_routes requires a broader production extension than that single
microcategory CLI route. Exact candidate membership policy:
  1. Preserve the original description449+dense449+geo100 UNIQUE pool B.
  2. Produce these four depth998 lists in this exact order:
     lexical_title_values,lexical_params_values,micro_combined_top3,dense_current.
     Typed lexical text is search_query+' '+extract_filter_values(search_params).
     Title BM25:k1=1,b=.2. Params BM25:k1=1.2,b=.7.
     Micro combined uses the same classifier and producer's normalized field
     scores/category allocation. Dense uses the unchanged current query input.
  3. For novel ID i outside B, addition_score(i)=sum[1/(60+rank(i))]
     over those four lists containing i. Ranks are the ORIGINAL per-list ranks
     before base IDs are removed. Weights are all1. Duplicate IDs within one
     list are invalid; an ID present in multiple lists receives multiple terms.
  4. Sort novel IDs by(-addition_score,item_id), then take first998-|B|.
  5. Candidate pool order for parity is original B order followed by that novel
     prefix. No old ID is removed or re-ranked to allocate candidate slots.
These addition-selection scores are NOT the final RRF/reranker score rule.
New-pool reranker training/features require a separately declared policy.
Simply turning on standard title/params BM25 weights or giving a new route a
positive final-RRF weight does not reproduce this protected four-list policy.
