DOCUMENT COMPLEMENT STUDY V1 — SCREEN AND FULL TUNE
2026-10-13

Scope and declaration
---------------------
This is a POSTHOC exploratory follow-up. The prior compact replacement result
(103 positive pairs found and 86 lost) motivated complementary views. The four
new candidate variants and their selection rule were written BEFORE outcomes
of this new contrast. This is not retroactive overall preregistration. Completed
Audit labels/report were never opened or used to choose variants or settings.

The encoder, 128-token maximum, sampled 200000-item catalog, ef_search 1000,
location bonus 0.02 and original protected candidate union were held fixed.
That union contains description top-449, current dense top-449 and geo top-100.
Every protected item is kept; novel IDs can fill only 998 minus its unique size.
No selected positive was inserted and native item IDs remain strings.

Existing sealed query-variants, lexical, micro and document-compact streams were
reused. No GPU, index, vector encoding, classifier inference or model training
was launched. Frozen evaluator, producer, helper and encoder source stayed intact.

The novel-candidate rule has equal route weights, reciprocal-rank constant 60,
ORIGINAL raw ranks before skipping protected IDs, and item-ID ties. This rule
chooses a candidate pool; it does not choose the final answer's top 50.

Declared route choices
----------------------
F_hybrid_routes (control): typed title, typed params, micro combined top-3,
                         and extra current-document dense neighbors.
F_compact_only:           compact-document dense neighbors only.
F_compact_instead_depth:  typed title, typed params, micro combined top-3,
                         and compact-document dense neighbors.
F_five_views:             all four control routes plus compact neighbors.

The original current dense top-449 remains PROTECTED in every variant. Thus
F_compact_instead_depth replaces only the additional-depth route, not the
current dense channel in the protected pool. Compact supplies its saved raw
top-449 list; current extra-depth supplies its saved raw top-998 list.

All variants share the 998-ID upper cap. Realized unique pool sizes can differ;
this does not isolate a causal effect of document formatting alone.

Interpretation and production decision boundary
----------------------------------------------
This is useful evidence of complementary retrieval signals: retaining the
original current dense candidates and using compact neighbors for some free
slots performs better here than using extra current dense depth for those slots.
Simply adding compact as a fifth equal-weight route did not win the screen.
Allocation and overlap matter alongside the document representation.

The full-Tune interval lies above zero, but this is still an exploratory effect:
the choice was informed by earlier compact outcomes, then selected on a screen
contained inside full Tune. The interval is uncorrected for this adaptive search.
It is not independent proof of a generalization or official-score improvement.

The measured quantity is candidate coverage, an upper bound for a final ranker.
No new-pool reranker Recall@50, official answer score or Audit evaluation was
measured by this study. Root's current-document V8 training continues unchanged.
The existing production four-route helper is not silently changed. Adopting a
second compact index and training/ranking features requires a later explicit
integration decision and separate exact-pool parity checks.

Token-retention analysis remains a mechanism hypothesis. These actual results
support testing complementary views, not increasing token length: length stayed
128 throughout, and direct compact replacement was previously inconclusive.

Reproduction
------------
CPU-only evaluator: OMP_NUM_THREADS=2, --batch-size 8192, --text-limit 2000 for
screen / 0 for full Tune, --bootstrap-replicates 2000, seed 20261013.
The four existing JSONL.gz streams and their complete '.gz.json' companions are
passed with repeated --supplement and --supplement-metadata arguments.
