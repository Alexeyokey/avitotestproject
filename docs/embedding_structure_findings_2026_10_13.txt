Структура эмбеддингов: проверенные причины и проверяемые гипотезы
Дата исследования: 2026-10-13. Длина зафиксирована: 128 токенов.

1. Dense уже даёт самостоятельный сигнал

По ранее зафиксированному Audit dense покрывал около 69,94% доступных
положительных объявлений, канал описания — около 52,20%. Их объединение
давало около 80,42%. Эти числа описывают прежний контроль; новые варианты
по Audit не выбирались. Малый прирост итоговых 50 нельзя приравнивать к
отсутствию полезных кандидатов у dense.

2. Ограничение текущего текста объявления

Текущий шаблон: название, категория, первые 40 слов параметров, первые
48 слов описания. В профиле по 5000 объявлениям параметры занимают
в среднем 79,063 токена. Описанию остаётся 18,839 токена; сохраняется
около 22,226% токенов от выбранного фрагмента описания. Для 6,803%
объявлений с непустым описанием оно полностью выходит за предел 128 токенов.

Компактный шаблон сохраняет название и смысловые значения параметров,
сокращая служебные ключи. В том же профиле описанию достаётся в среднем
63,042 токена; сохраняется около 62,367% выбранного фрагмента.
Полное выпадение описания снижается до 1,461%.

Это измерение распределения токенов. Прирост качества определяется
отдельным поисковым экспериментом на новых векторах тех же объявлений.
Полное исходное описание в 128 токенов по-прежнему не помещается.

3. Query-предобработка уже проверена отдельно

Экран: 2000 текстов Tune, все 3902 их контекста. У 988 текстов / 1515
контекстов есть доступные положительные объявления. Бюджет:449+449+100.
Основная метрика здесь: Recall пула, усреднённый сначала по контекстам
текста запроса, затем по текстам с доступными целями.

Текущий запрос:                 0,889722
Только текст запроса:           0,873193
Смысловые значения фильтров:     0,885505
Без категории:                 0,888204
Без инструкции модели:         0,888399

Ни один альтернативный запрос пока не принят. На всём Tune удаление
инструкции также уступило контролю:0,886868 против0,888645.
Конфигурация модели проверена: используется её query-инструкция,
pooling по последнему токену, include_prompt=True. Документная
инструкция сохранена. Подтверждённой ошибки pooling или двойной
инструкции не найдено.

4. Ограничения прежнего дообучения

Обучение использовало одну положительную пару на нормализованный текст:
59140 пар вместо 361150 уникальных fit-пар. Для 23559 текстов (39,84%)
известно несколько положительных объявлений. Такой выбор снижает риск
случайно сделать другой известный ответ отрицательным внутри батча,
но теряет часть разнообразия объявлений и контекстов.

Batch32 предоставляет не более31 внутрибатчевого отрицательного примера
на положительную пару. Увеличение батча меняет обучающую задачу;
неразмеченные объявления нельзя автоматически считать нерелевантными.
Мультипозитивное обучение с контролем ложных отрицательных — отдельная
возможная гипотеза, тяжёлый прогон которой ещё не объявляется завершённым.

5. Новые самостоятельные каналы

На полном Tune (6111 текстов / 12103 контекста) сохранён исходный пул
и заполнены свободные места четырьмя каналами: название со смысловыми
фильтрами, параметры со смысловыми фильтрами, top3 предсказанных
микрокатегорий, дополнительная глубина прежнего dense. Добавления
выбираются по RRF исходных рангов с равными весами и константой60.

Recall исходного пула:          0,8886449836014265
Recall объединённого пула:      0,9061678486179665
Разница:                       +0,01752286501654
Средний / максимальный пул:     998 / 998
Положительных пар добавлено:    85
Положительных пар потеряно:     0

Это исследовательская оценка Tune после выбора вариантов. Она не является
новой независимой проверкой или внешней оценкой готового answer.csv.
Вклада каждого отдельного канала из общей разницы вывести нельзя.
При одинаковом количестве добавлений microcombined превзошёл
typed-title на0,006619; преимущество над добавочной глубиной dense
на первоначальном экране было всего0,000802.

6. Что проверяется дальше

Изменение документного текста проверяется отдельно при прежних
128 токенах и тех же квотах. Соответствующий новый индекс не подменяет
исходный индекс. Для итогового выбора50 подготовлен V8-реранкер:
вероятности/ранги микрокатегорий и измеренная cosine для всего пула.
Вероятности на обучающих текстах получаются только из модели OOF,
которая не видела данного текста. Географическая история также
исключает текущий обучающий текст.

7. Почему нельзя сравнить числа с чужими решениями напрямую

Референсы изучены по зафиксированным коммитам:
https://github.com/boomchik93/AvitoDS_Bootcamp_TestTask/blob/956b6c8f3d2726f1f6f9b95114c5d6dd4f20743f/src/retrieval.py#L203-L260
https://github.com/serzhikWW/AvitoNLPTest/blob/82d12978989e0d6fc767b916f5b43502a9b775a2/src/ranker.py#L161-L224

В них есть отдельные сигналы названия, структурных параметров и
микрокатегорий. Состав каталогов и способ образования validation
отличаются от наших. В частности, выбор каталога с заранее включёнными
положительными validation-объявлениями задаёт другую поисковую задачу.
Сравнение архитектур полезно; сравнение абсолютных Recall без общего
протокола не показывает превосходство конкретного encoder.
