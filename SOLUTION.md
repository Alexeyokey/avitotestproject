# Описание решения

Задача — вернуть до 50 `item_id` из `benchmark_items.parquet` для каждого
запроса из `benchmark_queries.parquet`. Поиск состоит из формирования пула
кандидатов и выбора финальных 50. Код не обращается к API при оценке и
построении ответа; веса открытой модели эмбеддингов должны быть доступны
локально перед запуском.

## Данные и признаки

- `benchmark_items.parquet` — единственный корпус объявлений, из которого
  формируется ответ. Из заголовка, параметров и описания строятся отдельные
  текстовые индексы; `item_location_id` нужен географическим каналам. Для
  реранкера дополнительно используются категория, цена, рейтинг, число
  отзывов и признаки доступности связи.
- `benchmark_queries.parquet` — тексты запросов, локации, категория, фильтры
  и флаг поиска с доставкой. Текст нужен обоим поисковым каналам; остальные
  поля помогают выбрать кандидатов с подходящими условиями.
- `train.parquet` — известные выбранные пары. Они служат положительными
  примерами для локальной оценки и обучения реранкера. По обучающей части
  также считаются связи между локацией поиска и локациями выбранных
  объявлений; ответы отложенной части в эти связи не попадают.

Идентификаторы остаются строками. Общая нормализация текста приводит буквы
к нижнему регистру, заменяет `ё` на `е` и убирает лишние пробелы. Для
заголовка и параметров есть дополнительные BM25-каналы со стеммингом
русских слов. Фильтры используются как текстовые признаки; жёсткого
исключения объявлений по ним нет, поскольку их текст не всегда содержит
однозначное структурное условие.

## Алгоритмы

1. **BM25 по полям** независимо ищет по заголовкам, параметрам и описаниям.
   Включаемые отдельно каналы со стеммингом помогают при словоформах.
   Географические списки выбирают лучшие совпадения внутри подходящих
   локаций *до* ограничения глубины поиска; глобальные списки сохраняются.
2. **Семантический поиск** (`dense`/`hybrid`) кодирует запросы и объявления
   открытой моделью `Octen/Octen-Embedding-0.6B` через Sentence Transformers.
   Соседи по косинусной близости находятся в локальном индексе `hnswlib`.
   Модель может быть заменена локальным дообученным чекпойнтом.
3. **Объединение** в `bm25` и `hybrid` использует RRF. Совпадение точной
   локации добавляет настраиваемый балл только уже найденным объявлениям.
   Опциональный табличный реранкер на `HistGradientBoostingClassifier`
   выбирает 50 из того же пула. Ему передаются ранги и оценки каналов,
   RRF-балл, текстовые пересечения, соответствие локации и фильтрам,
   категория, цена, рейтинг и другие признаки объявления. Объявления без
   известного выбора используются как **неразмеченные**, а не как доказанно
   нерелевантные примеры.

Режимы и настройки описаны в [README](README.md). Реализация поиска находится
в `src/avito_candidates/baseline.py`, `dense.py`, `geography.py` и `hybrid.py`;
обучение — в `reranker.py`, команды и проверка формата — в `cli.py`.

## Проверка качества и найденные ошибки

Основная локальная проверка: `--split queries --seed 42`, 20% текстов
запросов целиком откладываются вместе со всеми локациями и фильтрами. Метрика
Recall@50 усредняется по группам запросов; дополнительно измеряются Recall
полного пула и качество отдельных каналов. Сравнение вариантов проводится
на одних и тех же группах и корпусе. Например, для BM25 с глубиной 500
добавление географических каналов подняло Recall пула с **0,8422 до 0,9472**,
а Recall@50 — с **0,7059 до 0,7699**. Отчёты и графики указаны в README.

Анализ выявил четыре существенных источника ошибок:

| Проблема | Что сделано |
| --- | --- |
| Положительное объявление отсутствует в корпусе локальной проверки | Такие пары не включаются в метрику; в отчёте отдельно показывается их доля. Это ограничение локальной оценки, а не ошибка модели. |
| Подходящее местное объявление не вошло в глобальный текстовый срез | Добавлены географические каналы, которые отбирают объявления до среза. |
| Сильный бонус локации вытесняет подходящих исполнителей из других мест | Бонус настраивается; в отчёте есть срезы по локации. Реранкер использует географию как признак, без жёсткого правила. |
| Известное объявление есть в пуле, но не попало в финальные 50 | Измеряются обе метрики; для отбора 50 добавлены признаки отдельных каналов и обучаемый реранкер. |

Локальная проверка не является точным прогнозом результата платформы: только
около **6,6%** строк train с выбранным объявлением относятся к корпусу
`benchmark_items.parquet`, а распределения фильтров в локальных и тестовых
запросах различаются. Поэтому в README результаты разных конфигураций
разделены, а оценка скрытого теста не трактуется как измерение конкретной
ошибки поиска или реранкера.

## Воспроизведение

Для воспроизводимого запуска нужны три исходных Parquet-файла в `dataset/`.
Установите зависимости по [инструкции](README.md#установка). Пример полностью
локального варианта без нейросетевой модели:

```bash
avito predict --data-dir dataset --method bm25 --candidate-k 500 \
  --stem-title-weight 0.5 --stem-params-weight 0.25 \
  --location-bonus 0.1 --bm25-channel-quota 0 --geo-candidate-k 100 \
  --answer artifacts/answer-geo-bm25.csv
avito validate --data-dir dataset --answer artifacts/answer-geo-bm25.csv
```

Эта команда повторно создала локальный `artifacts/answer-geo-bm25.csv`
**побайтово одинаковым**: SHA-256 обоих файлов —
`741d581006d6eb9796c0d914c857f27dc56fa085e12997c0aa98254bbca7c904`.
Для этой проверки SHA-256 входных файлов были:

| Файл | SHA-256 |
| --- | --- |
| `train.parquet` | `e150ab7a5c98769f643b95ee3a02dc0f664b647facd69a7d280ec6d48ca554a7` |
| `benchmark_items.parquet` | `193b3a3961464620cbf8d8797152b7f90cae1826ca749fb7817a210984a09899` |
| `benchmark_queries.parquet` | `e49de4fb76f03979a4af96034817767d39ae5de9f94e254fed028243188dda06` |

Результат другого варианта, в том числе с дообученной Octen или реранкером,
требует **его точной команды**, той же версии кода, локального чекпойнта и
файла обученной модели. README содержит команды для обучения и проверки,
но сам по себе пример выше не доказывает совпадение с файлом, отправленным
на платформу. Большие исходные данные, индексы и веса моделей в Git не
включены.

Использованы открытые библиотеки scikit-learn, NumPy, pandas, PyArrow,
Snowball Stemmer, Sentence Transformers и `hnswlib`. Все этапы после
получения данных и весов модели выполняются локально.
