# Обучение реранкера на дообученной Octen

Этот комплект содержит текущий исходный код, скрипт запуска, зависимости
и тесты. Если папка перенесена без датасета, файлы Parquet должны уже
находиться на ПК. Виртуальное окружение macOS и старые
HNSW-индексы не включены: на Linux они бесполезны или относятся к другой
версии модели. Чекпойнт **новой** Octen и исходный JSON-отчёт её оценки
находятся на другом ПК и должны остаться там. Скрипт их не скачивает.

## 1. Распаковать и проверить окружение

В WSL/Ubuntu распакуйте архив в отдельный каталог, откройте терминал в
распакованной папке `avito-reranker-new-octen` и активируйте уже настроенное
CUDA-окружение. Если окружения нет:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dense]'
```

PyTorch должен видеть видеокарту. Если он уже установлен в рабочем окружении,
переустанавливать его не нужно:

```bash
python -c 'import torch; print("CUDA:", torch.cuda.is_available())'
python -m unittest discover -s tests -q
```

Ожидается `CUDA: True` и успешные тесты. Для обучения и оценки нужны
`train.parquet` и `benchmark_items.parquet`. Если они лежат в другой папке,
укажите её полный путь через `--data-dir` в команде ниже вместо `dataset`.
`benchmark_queries.parquet` понадобится позже только для создания финального
ответа командой `avito predict`. При необходимости сравните версии файлов
по размеру или SHA-256.

## 2. Найти чекпойнт и исходный отчёт

Нужен **каталог сохранённой модели Sentence Transformers**, а не одиночный
файл адаптера LoRA. Проверка загрузки и сохранённых поисковых промптов:

```bash
export OCTEN_CHECKPOINT='/полный/путь/к/дообученной/Octen'
export OCTEN_REPORT='/полный/путь/к/artifacts/octen-lora-128-full-mb16-s42-eval.json'

python - <<'PY'
import os
from sentence_transformers import SentenceTransformer

model = SentenceTransformer(os.environ['OCTEN_CHECKPOINT'], device='cuda')
print('Размерность:', model.get_sentence_embedding_dimension())
print('Промпты:', sorted(model.prompts))
PY
```

Если промптов `query` и `document` нет, остановитесь и проверьте, каким
способом кодировались запросы и объявления при получении исходных 74,41%.
Разные промпты меняют эмбеддинги и требуют нового HNSW-индекса.

Исходный отчёт должен относиться к **полной дообученной** Octen на
`split=queries`, `seed=42`, с 5 157 оцениваемыми группами. Он нужен скрипту,
чтобы восстановить настройки BM25, dense и объединения каналов. Дополнительно
проверьте, что при дообучении Octen не использовались отложенные тексты
запросов из этого разбиения: иначе Recall на нём нельзя считать честной
валидацией.

## 3. Запустить эксперимент

```bash
python scripts/train_reranker_new_octen.py \
  --source-report "$OCTEN_REPORT" \
  --embedding-model "$OCTEN_CHECKPOINT" \
  --data-dir dataset --device cuda \
  --embedding-batch-size 16 --embedding-max-length 128 \
  --ef-search 300 \
  --target-candidate-k 500 --target-geo-candidate-k 100 \
  --output-dir artifacts/reranker-new-octen
```

Если прежняя проверка Octen использовала другой `ef-search`, укажите здесь
именно то значение. Исходный JSON обычно не сохраняет этот параметр, поэтому
он задаётся отдельно. Для предварительного просмотра команд добавьте
`--dry-run`.

Скрипт последовательно:

1. Повторяет оценку Octen с исходной глубиной и проверяет, что Recall@50
   отличается от значения в исходном отчёте не более чем на 0,005.
2. Формирует обучающие признаки реранкера на **всех** доступных группах
   обучающей части (`split=queries`, ограничение числа запросов не задано).
   Для итогового пула берёт глубину 500 и до 100 дополнительных объявлений
   на географический канал. Неизвестные объявления используются как
   неразмеченные отрицательные примеры.
3. В отдельном процессе обучает `HistGradientBoostingClassifier` на рангах
   и исходных оценках BM25/dense, признаках географии, фильтров и объявления.
4. На тех же 5 157 отложенных группах сравнивает обученный реранкер с
   исходным RRF **при одинаковом расширенном пуле**.

Первый проход может строить новый HNSW-индекс и поэтому быть долгим. Индекс
сохраняется в `artifacts/dense` с учётом состояния локального чекпойнта.
Не редактируйте файлы чекпойнта во время построения индекса.

## 4. Что смотреть в результате

Итоговый отчёт:
`artifacts/reranker-new-octen/heldout-eval.json`.
Основные поля:

- `retrieval_diagnostics.candidate_pool_recall` — потолок Recall@50 для
  отбора из сформированного пула;
- `retrieval_diagnostics.baseline_recall_at_50` — RRF без реранкера на этом
  же пуле;
- `recall_at_50` — результат реранкера;
- `retrieval_diagnostics.reranker_delta_at_50` — парная разница двух вариантов.

Не сравнивайте итоговый результат напрямую с 74,41% как эффект реранкера:
итоговый пул дополнительно расширен. Эффект обучения показывает именно
`reranker_delta_at_50`. Отдельно проверьте географические срезы и качество
запросов с фильтрами: средний Recall может скрыть ухудшение одной группы.

Скрипт сохранит также `reference-reproduced.json`, `train.parquet`,
`train.parquet.json`, `model.joblib` и CSV с итоговыми RRF-баллами. Если
воспроизведение исходных 74,41% не прошло, обучение останавливается до
создания признаков; проверьте чекпойнт, промпты, `ef-search` и исходную
команду оценки.

Все расчёты выполняются локально. После установки зависимостей внешние API
для обучения и оценки не используются.
