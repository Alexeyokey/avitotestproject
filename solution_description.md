# Решение для Recall@50

## Поиск кандидатов

Объявления кодируются локальной `Octen/Octen-Embedding-0.6B`, дообученной на парах из `train.parquet` с помощью LoRA. В текст объявления входят заголовок, категория, начало параметров и описания; максимальная длина — 128 токенов. По эмбеддингам строится локальный HNSW-индекс. Для запроса берутся 449 dense-кандидатов (`ef_search=1000`).

Отдельно BM25 ищет 449 объявлений по описанию и 100 объявлений в географическом канале. Для географического канала используются связи локации поиска с локациями выбранных объявлений, оценённые только по обучающим строкам. Совпадение точной локации добавляет 0,02 к RRF-баллу. Объединение каналов даёт не более 998 уникальных кандидатов до отбора 50.

## Реранкер

`HistGradientBoostingClassifier` выбирает финальные 50 из пула. Он получает ранги и исходные оценки поисковых каналов, совпадение текста и фильтров, характеристики объявления, статистику локаций, а также вероятность и ранг микрокатегории объявления по словам запроса. Категорийная и географическая статистика для проверки строится исключительно на обучающей части. При подготовке обучающих строк собственный текст запроса исключается из категорийной статистики.

Модель обучается на выбранных объявлениях как положительных примерах и на кандидатах без зарегистрированного выбора как **неразмеченных** примерах. На запрос берётся до 64 таких кандидатов. Для финальной модели используется максимум 20 000 групп запросов из всего `train.parquet`, `seed=42`, 150 итераций бустинга.

## Локальная проверка

На разбиении по текстам запросов (`split=queries`, `seed=42`) реранкер обучался на 21 392 группах и проверялся на 5 157 ранее невидимых группах. При одинаковом пуле Recall@50 исходного отбора был 0,80313, прежнего реранкера — 0,81985, новой модели — **0,84376**. Recall пула — 0,91664, средний размер — 783,47. Парный прирост новой модели к прежней — 0,02391; 95% кластерный bootstrap-интервал по текстам запросов: [0,01723; 0,03114]. Это локальная оценка, а не результат скрытой проверки.

## Воспроизведение

Для инференса нужны три исходных Parquet-файла, исходники проекта, локальные веса базовой Octen и сохранённый LoRA-чекпойнт, а также обученный файл реранкера. При подготовленных файлах инференс полностью локальный и не обращается к внешним API. Команда `avito predict` пишет ровно две колонки `query_id,answer` и сама проверяет количество строк, формат идентификаторов, отсутствие дублей и наличие объявлений в корпусе.

Используются open-source библиотеки `numpy`, `pandas`, `pyarrow`, `scikit-learn`, `joblib`, `snowballstemmer`, `PyTorch`, `sentence-transformers` и `hnswlib`; базовая модель — `Octen/Octen-Embedding-0.6B`.
