# Avito: кандидаты объявлений услуг

Локальный воспроизводимый пайплайн для Recall@50. Первая версия — контрольная
точка: история выбора + словный TF-IDF по заголовкам и параметрам + weighted RRF.
Это не финальное оптимизированное решение. Код не использует query_id как признак.

## Запуск

Python 3.11+. Создайте виртуальное окружение и выполните `pip install -e .`.
В `dataset/` должны лежать три предоставленных Parquet. Путь можно заменить
на абсолютный в каждой команде; копировать исходные файлы необязательно.

```shell
python -m unittest discover -s tests -v
avito profile --data-dir dataset --output artifacts/profile.json
avito evaluate --data-dir dataset --split pairs --output artifacts/pairs.json
avito evaluate --data-dir dataset --split queries --output artifacts/queries.json
avito predict --data-dir dataset --answer artifacts/answer.csv
avito validate --data-dir dataset --answer artifacts/answer.csv
```

`--max-queries 200` ограничивает evaluate для быстрой проверки работоспособности;
это не полноценная оценка. Predict всегда обрабатывает весь benchmark.
Инференс и оценка не обращаются к внешним API. Интернет нужен только для установки.

## Валидация

Pairs: SHA-256 от полного нормализованного запроса и item_id назначает 20% пар
в holdout; дубли пары остаются вместе. Queries: откладываются целиком тексты
запросов, включая все локации и фильтры. История строится исключительно по fit.
Корпус объявлений доступен целиком, включая тексты отложенных объявлений.
Метрика — среднее Recall@50 по группам полных признаков запроса, а не по строкам.
При отсутствии session/query ID в train это приближение к benchmark-группировке.
В знаменатель входят только объявления корпуса; отчёт показывает покрытие holdout.
Pairs может сохранять ту же пару текст–объявление с другими фильтрами в fit:
проверка queries отдельно показывает обобщение на новые тексты.

## Порядок развития и перенос RAG

1. Измерить пересечения данных и два baseline Recall@50.
2. Перенести адаптированное поисковое ядро из пользовательского rag_project_qwen36:
   dense, два BM25-канала, RRF, диагностику. Один item_id — одна запись.
3. Разделить per_channel_k, merged_pool_k и output_k=50; подобрать на holdout.
4. Добавить локацию, фильтры, категорию и статистику train; проверить CatBoost.
5. Проверить прирост от CrossEncoder и обучения эмбеддингов.

Генератор Qwen, crawler, чат, Docling и judge-метрики не нужны для первой версии.
RAG-код пока не скопирован: сначала нужна измеримая контрольная точка.
У исходного RAG README расходится с кодом по весам BM25: код даёт полный вес
каждому каналу. При переносе веса будут задаваться явно. Для модели эмбеддингов
необходимо сохранить соответствующие ей pooling и формат входа.

## Зависимости и ограничения

Используются open-source pandas, PyArrow, NumPy и scikit-learn; TF-IDF и RRF —
стандартные методы поиска. Нейросетевых весов в первой версии нет.
Описание объявления пока не индексируется; нет морфологии и семантического поиска.
Фильтры и локация используются только как ключи истории, не как жёсткие ограничения.
При нехватке кандидатов выдача дополняется популярными в fit объявлениями корпуса.
Четыре канала имеют равные, пока не подобранные веса; каналы истории коррелируют.

Исходные данные, предсказания, индексы, веса и секреты не публикуются в Git.
